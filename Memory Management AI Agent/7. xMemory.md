Based on the **xMemory** framework described in the source, here are the short answers to your questions:

- **Formation (What becomes a memory?):** Raw interaction history is partitioned into **segments** representing local events, which are then decoupled into **memory components** (reusable facts, constraints, and updates),,.
- **Representation (How is memory represented?):** A **revisable hierarchical structure** consisting of original messages, segments, memory components (textual description + embedding + pointer), and high-level groups,,.
- **Storage (Where is it stored?):** **None** (The source focuses on the hierarchical organization and "memory store" structure rather than naming a specific storage backend),,.
- **Memory Type (What kinds of memory exist?):** **Episodic segments** (local event context) and **aggregated semantic groups** (compact high-level access units),,,.
- **Retrieval (How memories are retrieved?):** A **top-down adaptive process**; Stage I selects a high-level backbone of groups/components, and Stage II expands into segments/messages only if it reduces "reader uncertainty",,,.
- **Ranking (How are retrieved memories prioritized?):** By **balancing structural coverage** (using kNN links to avoid redundancy) **against query relevance** (similarity),,.
- **Update (How does existing memory update after new context?):** Through **retroactive restructuring**; new interactions can trigger **split** (partitioning broad groups) or **merge** (combining small groups) operations to reorganize previously stored components,,,.
- **Compressed (How are memories compressed/combined?):** Interactions are **decoupled into concise evidence units** and then aggregated into higher-level groups to provide a compact, coherent index,,.
- **Forgetting (How memory forget unnecessary context?):** The system uses a **distillation filter** during extraction to skip "transient conversation details" and stops text expansion during retrieval once uncertainty is minimized,,,.
- **Conflict (What happens when memories disagree or conflict occur?):** The system is prompted to **prioritize the most recent memory** based on its timestamp,,.
- **Temporal (How is time handled?):** Every memory is **temporally anchored** with a timestamp; the system converts relative time references (e.g., "last year") into absolute dates,,,.
- **Memory Importance (How is memory importance determined?):** Using **High-Value Knowledge Criteria** (Persistence, Specificity, Utility, and Independence tests) during the extraction phase,.
- **Controller (Who makes memory decisions?):** An **LLM** (acting as an expert) manages boundary detection, episodic generation, and component extraction,,,.
- **Trigger (When does memory management happen?):** Segmentation and extraction happen **incrementally/online** as messages arrive; split/merge operations are triggered **periodically** or when size/coherence thresholds are crossed,,.
- **Feedback (Does future usefulness influence memory?):** **Yes**, the "Utility Test" specifically evaluates if a memory can "help predict future user needs".
