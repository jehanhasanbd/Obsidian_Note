Based on the provided source, here is a concise summary of the memory management aspects for the **FluxMem** framework:

- **Formation (What becomes a memory?):** Individual user-agent interaction pages (dialogue history).
- **Representation (How is memory represented?):** Interaction pages with metadata/timestamps; MTEM uses summaries and indexing structures including **linear** (chronological), **graph** (relational), and **hierarchical** (topic-based).
- **Storage (Where is it stored?):** A three-layer hierarchy: **STIM** (Short-Term Interaction Memory), **MTEM** (Mid-Term Episodic Memory), and **LTSM** (Long-Term Semantic Memory).
- **Memory Type (What kinds of memory exist?):** Short-term, mid-term episodic, and long-term semantic.
- **Retrieval (How memories are retrieved?):** Hybrid retrieval combining dense encoding and BM25 via reciprocal rank fusion; MTEM retrieval follows structure-specific strategies (e.g., DFS for hierarchies).
- **Ranking (How are retrieved memories prioritized?):** Prioritized based on an **episodic utility score** (frequency, intensity, and recency) and similarity-based ranking.
- **Update (How does existing memory update after new context?):** A stage-wise pipeline where pages move from STIM to MTEM, then consolidate into LTSM.
- **Compressed (How are memories compressed/combined?):** MTEM groups semantically related pages into coherent sessions/episodic units with abstracted summaries.
- **Forgetting (How memory forget unnecessary context?):** STIM uses a **Least Recently Used (LRU)** policy; MTEM and LTSM use **utility-aware and eligibility-based pruning** (usage, recency, and confidence).
- **Conflict (What happens when memories disagree or conflict occur?):** None.
- **Temporal (How is time handled?):** STIM uses recency-based access; linear memory preserves chronological acquisition order; sessions include timestamps to resolve time-dependent queries.
- **Memory Importance (How is memory importance determined?):** Calculated via episodic utility scores (MTEM) and usage/recency/confidence thresholds (LTSM).
- **Controller (Who makes memory decisions?):** A lightweight **MLP-based structure selector** and a **Beta Mixture Model (BMM)** gate for fusion decisions.
- **Trigger (When does memory management happen?):** At each interaction turn and when memory capacity limits are exceeded.
- **Feedback (Does future usefulness influence memory?):** Yes; the selector is trained using **offline supervision** derived from rewards for response quality and memory utilization.
- **Cost (How expensive is management?):** Negligible overhead compared to LLM decoding; the MLP selector and BMM gate add minor, constant, or linear-time costs.
