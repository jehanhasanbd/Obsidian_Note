Based on the **H-MEM (Hierarchical Memory)** framework described in the source, here are the short answers to your questions:

- **Formation (What becomes a memory?):** Interactions are parsed into **multi-level structured information**, including high-level domains, categories, keywords, and specific events/user profiles.
- **Representation (How is memory represented?):** As **dense semantic vectors** embedded with **positional index encodings** that point to related sub-memories in the next layer.
- **Storage (Where is it stored?):** In a **four-level hierarchical structure** (Domain, Category, Memory Trace, and Episode layers) resembling the organization of a document.
- **Memory Type (What kinds of memory exist?):** **Episodic memory** (fine-grained interaction details and events) and **semantic memory** (abstract summaries and categories).
- **Retrieval (How memories are retrieved?):** Via a **top-down memory traversal** and index-based routing mechanism using FAISS for similarity calculations layer-by-layer.
- **Ranking (How are retrieved memories prioritized?):** Using **similarity-based top-k selection** at each layer to filter relevant memory units recursively.
- **Update (How does existing memory update after new context?):** **External memory weights** are dynamically adjusted based on user feedback (approval, no feedback, or rebuttal).
- **Compressed (How are memories compressed/combined?):** Interactions are **abstracted and summarized** into directories at higher layers (Domain and Category) while preserving fine-grained details in lower layers.
- **Forgetting (How memory forget unnecessary context?):** Follows the **Ebbinghaus Forgetting Curve** for "Natural Shrink" and reduces weights if a user refutes a memory.
- **Conflict (What happens when memories disagree or conflict occur?):** **None** (The paper notes that user rebuttal reduces a memory's weight, but does not detail a specific internal resolution for conflicting memories).
- **Temporal (How is time handled?):** The Episode Layer stores **interaction timestamps** and capture fine-grained, temporally grounded interaction details.
- **Memory Importance (How is memory importance determined?):** By **external memory weights** that are reinforced by usage and approval or decayed by neglect and rebuttal.
- **Controller (Who makes memory decisions?):** A **specialized memory extraction model** (LLM) manages storage, while an index-based routing logic manages retrieval.
- **Trigger (When does memory management happen?):** Extraction is invoked **after each interaction** between the user and the large language model.
- **Feedback (Does future usefulness influence memory?):** **None**.
- **Cost (How expensive is management?) [token per query]:** **None** (The paper evaluates efficiency in terms of "Compute Operations" and latency in milliseconds, but does not provide a tokens-per-query metric).
