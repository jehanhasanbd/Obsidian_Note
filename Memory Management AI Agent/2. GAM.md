Based on the **GAM (Hierarchical Graph-based Agentic Memory)** framework described in the sources, here are the short answers to your questions:

- **Formation (What becomes a memory?):** **Atomic interaction units** (user utterances and system responses) are captured in real-time and later consolidated into high-level **semantic clusters or themes** upon topic shifts.
- **Representation (How is memory represented?):** A **hierarchical graph (\(H_t\))** consisting of a global **Topic Associative Network** (\(G_{topic}\)) and local **Event Progression Graphs** (\(G_{event}\)), bridged by cross-layer links.
- **Storage (Where is it stored?):** Memory is stored in a **decoupled graph architecture** that separates active buffers (local context) from consolidated global knowledge and historical archives (\(S_{arch}\)).
- **Memory Type (What kinds of memory exist?):** The system maintains **episodic memory** (individual interaction events) and **semantic memory** (consolidated abstract themes and clusters).
- **Retrieval (How memories are retrieved?):** Via a **Graph-Guided Retrieval** strategy that performs a top-down traversal starting from semantic anchors in the global network down to archived episodic details.
- **Ranking (How are retrieved memories prioritized?):** Using **Multi-Factor Re-ranking** where semantic relevance is modulated by **temporal signals**, **intrinsic confidence**, and **role-centric** contextual factors.
- **Update (How does existing memory update after new context?):** Through a **Semantic Consolidation Phase** where buffered context is summarized and integrated as new nodes and edges into the global network when a topic boundary is detected.
- **Compressed (How are memories compressed/combined?):** Consolidated nodes use a **dual-granularity representation** consisting of a concise LLM-generated summary (\(c_{sum}\)) and the raw textual content (\(c_{raw}\)).
- **Forgetting (How memory forget unnecessary context?):** The system employs **write isolation** to shield the global store from "transient noise" and resets the local active buffer after every consolidation phase.
- **Conflict (What happens when memories disagree or conflict occur?):** The framework defines specific **edge types like "contradict"**; inaccurate beliefs can be corrected by adjusting confidence weights or removing spurious edges/nodes.
- **Temporal (How is time handled?):** Handled via **sequential edges** in the Event Progression Graphs and a **temporal boosting factor** (\(\beta_{time}\)) during retrieval to prioritize chronologically relevant context.
- **Memory Importance (How is memory importance determined?):** Importance is quantified as **edge weights** determined by an LLM-based semantic scorer (confidence scores) and by **query-specific relevance** during retrieval.
- **Controller (Who makes memory decisions?):** An **LLM-driven state machine** (acting as a neural proxy for the thresholding function) manages the transitions between buffering and consolidation.
- **Trigger (When does memory management happen?):** Triggered by **semantic divergence detection** (finding topic boundaries) or sparse maintenance events like session-end, interaction pauses, or buffer overflow.
- **Feedback (Does future usefulness influence memory?):** **None** (the paper approximates future interference with a semantic indicator but does not explicitly use "future usefulness" as a direct storage metric).
- **Cost (How expensive is management?):** The system is highly efficient, reducing token consumption to **1,370 tokens per query** (an 11% reduction compared to baselines like Mem0).
