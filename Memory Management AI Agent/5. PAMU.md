Based on the **PAMU (Preference-Aware Memory Update)** framework described in the source, here are the short answers to your questions:

- **Formation (What becomes a memory?):** Multidimensional **user preference signals** (tone style, response length, emotional tone, information density, and formality) extracted from multi-turn interactions,.
- **Representation (How is memory represented?):** A **multidimensional preference vector** (\(P\)) containing continuous scalar values and categorical probability distributions,.
- **Storage (Where is it stored?):** **None** (The paper describes PAMU as a modular mechanism that constructs/updates a vector for prompt injection rather than a standalone storage architecture),.
- **Memory Type (What kinds of memory exist?):** **Preference memory**, categorized into short-term behavioral fluctuations and long-term user tendencies,.
- **Retrieval (How memories are retrieved?):** **None** (It functions via dynamic prompt engineering and injection of the current preference state rather than database retrieval),.
- **Ranking (How are retrieved memories prioritized?):** **None**.
- **Update (How does existing memory update after new context?):** Through a **weighted fusion** of Sliding Window (SW) averages for recent shifts and Exponential Moving Average (EMA) for historical stability,,.
- **Compressed (How are memories compressed/combined?):** Continuous preference scores are **discretized into semantic tags** (e.g., "brief," "dense") and verbalized into concise natural language instructions,.
- **Forgetting (How memory forget unnecessary context?):** EMA applies **exponential decay** to historical data to filter out "transient noise" and emphasize current trends,,.
- **Conflict (What happens when memories disagree or conflict occur?):** A divergence signal detects conflicts; the system **prioritizes the short-term SW estimate** to reflect the user's most recent intent,.
- **Temporal (How is time handled?):** Time is modeled through **time-series analysis** techniques (SW and EMA) that track preferences turn-by-turn,,.
- **Memory Importance (How is memory importance determined?):** Importance is based on the **divergence between short- and long-term signals**; updates are triggered if the deviation exceeds a threshold (\(\delta\)),.
- **Controller (Who makes memory decisions?):** The **Preference Dynamics Perception Module** (also referred to as the Preference Shift Detector),.
- **Trigger (When does memory management happen?):** Preferences are extracted **after each dialogue turn**; prompt updates are triggered when a significant preference shift is detected,.
- **Feedback (Does future usefulness influence memory?):** **None**.
- **Cost (How expensive is management?) [token per query]:** **None** (The paper evaluates performance using F1 and BLUE-1 scores but does not provide a specific tokens-per-query cost metric),.
