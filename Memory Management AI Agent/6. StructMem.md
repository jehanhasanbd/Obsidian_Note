Based on the **StructMem** framework described in the source, here are the short answers to your questions:

- **Formation (What becomes a memory?):** Factual and relational entries describing event content and interpersonal dynamics are extracted from dialogue utterances.
- **Representation (How is memory represented?):** As **event-level units** consisting of natural language text and dense semantic embeddings anchored to specific timestamps.
- **Storage (Where is it stored?):** Memory is stored in a hierarchical structure comprising an **event buffer** for temporary storage and a persistent memory store.
- **Memory Type (What kinds of memory exist?):** **Episodic memory** (individual atomic entries) and a **consolidated abstraction layer** (synthesized cross-event relational hypotheses).
- **Retrieval (How memories are retrieved?):** Via a **dual-circuit retrieval** mechanism that uses cosine similarity to fetch both atomic entries and consolidated summaries.
- **Ranking (How are retrieved memories prioritized?):** Historical entries are ranked based on **cosine similarity** between their embeddings and an aggregated query vector.
- **Update (How does existing memory update after new context?):** **None** (The paper notes that it currently lacks an explicit revision process for updating existing information as context evolves).
- **Compressed (How are memories compressed/combined?):** Through **periodic semantic consolidation**, where semantically related event clusters are synthesized into higher-level relational summaries.
- **Forgetting (How memory forget unnecessary context?):** **None** (The authors identify the lack of a memory decay or updating strategy as a current limitation).
- **Conflict (What happens when memories disagree or conflict occur?):** **None** (The framework lacks an explicit mechanism for conflict resolution).
- **Temporal (How is time handled?):** Every memory entry is **temporally anchored** to its originating timestamp to preserve chronological and causal context.
- **Memory Importance (How is memory importance determined?):** Importance is determined by **semantic relevance** to the current context during the consolidation and retrieval phases.
- **Controller (Who makes memory decisions?):** An **LLM** (specifically GPT-4o-mini in experiments) guided by specialized prompts for extraction, synthesis, and retrieval.
- **Trigger (When does memory management happen?):** Consolidation synthesis is triggered **periodically** whenever the accumulated events in the buffer exceed a set time threshold.
- **Feedback (Does future usefulness influence memory?):** **None**.
- **Cost (How expensive is management?) [token per query]:** **None** (While the paper notes that it reduces token usage compared to baselines, it does not provide a specific "tokens per query" metric).
